## 1. 问题陈述（谁在流血）

微信公众号官方后台数据能力残缺，运营者做**数据复盘/周报/长期趋势分析**时被迫手动抄数：
- 官方数据导出功能弱，无法批量导出历史，长期趋势分析做不了（jzl.com/news/gzhdata：「导出麻烦。官方后台的数据导出功能很弱，你想做长期的数据追踪和趋势分析，用后台数据很难实现」）
- 后台部分数据保留周期短，错过截图就丢失增长曲线（g.jzl.com/news/19801 运营者一手叙述）
- 手动统计误差率高达 15%，多账号跨平台汇总频繁数据错位（jzl.com/news/171）
- 手动抄一周数据到 Excel，五个账号一上午没了（g.jzl.com/news/19283 运营者自述）

自家一手亲证（2026-10-16）：为读自家完读率，被迫 CDP 逆向 datacubequery 接口 + token/fingerprint 机制，踩坑清单——datacube 仅 7 天窗口、当天数据 T+1 滞后、draft/batchget API 返回假 0、publish_page 双重 JSON 编码。**这个信息差我们自己刚用时间付过费。**

## 3. 目标用户画像（细分）

**P-A 个人号主 / solo 技术型运营（首要画像）**
- 现状：1 个号、粉丝几百到几千、无预算或预算 <30 元/月
- 痛点场景：想知道「哪篇完读率高、推荐流占比多少」但后台翻页麻烦、数据过期即失；99 元/月的壹伴为用不上 60 个功能付费不划算
- 决策链：自己=使用者=付款人，看到技术文即可转化
- 与我们最近（我们就是 P-A），需求传感器最灵敏

**P-B 小团队新媒体运营（1-5 人，需向上汇报）**
- 痛点场景：每周/月要产出数据周报向上汇报（woshipm.com/operate/3375626 描述的 Excel 手工报表体系即此人群的笨办法）；手动整理一上午
- 付费意愿：止血型（省时+汇报质量），公司报销可能
- 获客路径：技术文/运营社区（jzl、woshipm 读者群）

**P-C 多账号矩阵运营者**
- 痛点场景：跨账号汇总数据错位（E5）；壹伴多账号管理在贵价档
- 验证优先级最低：需求被 E5 覆盖但获客难，MVP 不主打

**反画像（不做）**：企业级竞品分析/投放选号需求（新榜/西瓜/极致了领地，估算数据+数万元年费，重销售）——我们只做「自己后台数据的自动化」，不做外部数据估算。

## 4. 竞品分析

| 竞品 | 有什么 | 缺什么/弱点 | 我们的差异化 |
|---|---|---|---|
| 壹伴助手（明略） | 60+ 功能全家桶：排版/素材/数据导出/AI 诊断；200 万安装、年入千万 | ①99 元/月起，为单一数据需求买全家桶不划算；②重插件+账号绑定，安装与信任门槛；③知乎有付费用户差评（素材乱码+售后推脱，zhihu.com/question/369591887） | 单一用途、轻形态、低价档；无需绑定第三方账号（本地脚本用自己凭据，数据不出自己机器） |
| 新榜/西瓜数据/极致了 | 竞品监测、行业榜、投放选号 | 估算数据误差 10-30%（用户实测，g.jzl.com/news/19801）；数百-数万元/年，面向企业 | 只做自有后台**精确**数据，不做估算 |
| 考拉新媒体助手 | 「一键获取微信公众号统计数据」（27sem.com/article/532 提及） | 同为全家桶插件形态，知名度低于壹伴 | 同上 |
| 官方后台 | 免费、最准 | 导出弱、无批量历史、部分数据 30 天即失、无自动周报 | 全部官方缺口即我们功能清单 |
| CSDN 笨方法教程 | 免费 Excel 手工流 | 纯手工，每周重复劳动 | 把该教程自动化 |

**技术壁垒（一手）**：datacubequery 端点 + token/fingerprint 续期 + T+1/draft 假 0/publish 双重编码这些坑，全网无公开文档（E7 显示连开源作者都答「不能」获取互动数据）。逆向知识=短期内不易复制的 Cornered Resource（P10）。

## 5. 需求假设（可证伪表述）

- H1：存在 ≥20 个愿意留下联系方式表达「愿意为 9.9 元/月级自动周报付费」的公众号运营者（2 周内可验证）
- H2：P-A/P-B 人群对「数据不出本机/不绑第三方账号」有正向偏好（合规焦虑真实存在）
- H3：完读率/推荐流占比等推荐时代指标比阅读量更被关心（P7 佐证，待验证文评论区确认）

## 6. 零成本验证实验设计（预写判定规则，P3）

**实验 V1：踩坑实录技术文**
- 内容：《公众号后台数据自动化的一周踩坑实录》（素材全有：5 个坑+解法+图）；文末留资钩子：「想要 9.9 元/月级自动周报工具的留邮箱/进群」
- 渠道：掘金 + V2EX（分享创造）+ 自家公众号草稿（公众号版走 drafts-only，先 skill_view wechat-article-craft）
- 判定（预写）：2 周内 ≥20 人留资 = H1 通过 → 提案进阶段 1 PRD 并启动开发决策；5-19 人 = 弱信号，迭代文案/渠道再跑一轮；<5 人 = P1 证伪，C1 归档回 exploration.md，不投入开发
- 副作用正向：技术文本身反哺主路径内容资产（P13）

**合规红线**：实验阶段只做「教程+留资」，不碰用户凭据、不做托管服务（微信 ToS 灰色区留待用户决策，见 STATE.md 风险栏）。
